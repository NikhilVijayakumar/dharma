# Executive Suites - Atomic Universal Specification

## A. Operational Intent
Render domain-specific executive telemetry workspaces for fiscal, strategy, engineering, compliance, and operations decisions.

## B. Registry Dependency
- Agent Profiles: arya, nora, julia, mira, maya
- Skills: financial-forecasting, strategic-alignment, execution-governance
- Protocols: capital-allocation-protocol, risk-management-protocol, crisis-lockdown-protocol
- Workflows: arya/seed-autonomous-alignment, nora/sop-autonomous-fiscal-monitoring

## C. The Triple-Engine Extraction Logic
### OpenCLAW
Model cross-domain trade-offs and recommend action packs with quantified risk/return.

### Goose
Extract incoming metrics into suite-ready analytical tasks and dependency order.

### NemoClaw
Bind to suite tabs, KPI cards, scenario toggles, and drill-down ledgers.

## D. Hybrid Data Lifecycle
### SQLite (High-Performance)
Store high-frequency metric projections, scenario cache, and interaction state for fast dashboards.

### Vault (Secure Commit State)
Commit board-ready snapshots, approved plans, and crisis-mode decision records.

## E. Channel and Execution
- Cronjobs: Hourly refresh plus end-of-day consolidation.
- Internal Chat: Cross-executive coordination channel with suite references.
- External Channels: Telegram summary for critical runway and outage alerts.
- Dynamic UI Contract: Render form fields, thresholds, and stage controls directly from registry YAML/JSON schemas; do not hardcode input contracts.
- No-Dead-End Navigation: Every detail page must expose Back to previous context and Home to workspace root to satisfy Electron no-URL flow constraints.
- Manual Override: Every registry-backed view must show Current State and Proposed Improvement side-by-side before commit.
