# Interface: External Chat Routing - Atomic Feature Specification

## 1. Single Reason to Change (SRP)
This document handles updates **exclusively** related to formatting, filtering, and transmitting system payloads across the boundary to external networks (like Telegram bots or third-party webhooks). 

## 2. Input Data Required
- **Destination:** Webhook URI or internal Channel ID.
- **Payload:** Dispatches generated by KPI Alerting or Daily/Funding summaries.

## 3. Registry Sub-Component Integration
- **Agents:** `mira` (communications dispatcher).
- **Skills:** None.
- **Workflows:** The final execution node of delivery workflows.
- **Protocols:** Strictly bound by the `privacy-by-design-protocol` preventing internal ID leakage.
- **KPIs:** Not applicable.
- **Data Inputs:** Not applicable.

## 4. Triple-Engine Extraction Model
- **OpenCLAW:** Enforces a rigid Pre-Flight Security Check on the outgoing string. If the JSON or Text contains a string matching internal Vault keys or unapproved IP addresses, the dispatch is fundamentally halted.
- **Goose:** Translates complex system JSON objects into consumer-grade, readable Telegram Markdown (e.g., stripping UUIDs from error logs before sending to users).
- **NemoClaw:** Not applicable (headless network execution).

## 5. Hybrid DB & State Storage Flow
- **Generation:** Pulled in memory.
- **Commitment:** A 200 OK delivery receipt is logged into the **Vault** representing a non-repudiable Proof of Delivery.

## 6. Chat Scenarios (Internal vs External)
- **External Chat:** This IS the explicit bridge. It executes the logic delivering the Daily Brief, the Investor Summary, or the Critical SLA Breach Alert to the outside world.

## 7. Cron & Queue Management
- **Queue Management:** Requires a distinct Outbound Retry Queue.
- **Failover / Catch-up Mechanic:** If the local machine loses internet connectivity, the Telegram payload is paused dynamically in the Outbound Queue. Upon connection restoring, an algorithmic backoff loop fires, pushing stale but critical alerts sequentially to prevent out-of-order narrative delivery.
