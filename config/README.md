# Dharma Config — example TOML per repository role

Proposal state — examples, not loaded by any runtime yet. Design rationale
lives in `docs/proposal/11-provider-config-and-repo-sync.md`.

| File | Role | Lives in |
|---|---|---|
| `dharma-build.toml` | Dharma's own repository — self-tooling (build/docs/test), no MCP protocol role | `dharma`'s own root |
| `dharma-domain.toml` | A Domain System provider (e.g. the role Kriti plays for Samgraha's `rust_dev`) | that provider repository's root |
| `dharma-agent.toml` | An Agent System provider (e.g. `rust-development`, `documentation-management`, `story-telling`) | that provider repository's root |
| `dharma-repo.toml` | A consuming repository — selects a Domain System, registers with MCP | that repository's root |

Only `dharma-repo.toml`'s repository ends up with a `.dharma/` directory
(`repo.db` + `domain-summary.md` + `agent-summary.md`, all generated by
Dharma's sync flow) — provider repositories (`dharma-domain.toml`,
`dharma-agent.toml`) are captured *from*, never synced *into*.

See `env/` for the matching `.env.example` per role — every `${VAR}`
placeholder above resolves from there, same convention as samgraha's
`samgraha.toml` / `.env.example` pair.
